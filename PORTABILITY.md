# Linux and Windows portability audit

Reviewed 7 September 2026 against this repository's `Brewfile` and `install.sh`. No installation or configuration script was executed.

**Not everything transfers. Most of the developer/CLI environment is portable to Linux; Apple-specific desktop apps and Apple build workflows are the main losses. Neither Linux distribution can satisfy this list entirely from its default repositories.**

Scope: every **active** Brewfile package is listed below: **130 formulae, 100 casks, 31 Mac App Store apps**. Seven active taps are repository declarations, not seven additional applications. The 110 commented-out package entries are inventoried separately at the end; they are not installed by this script and were not individually researched.

Assumption: an x86-64 PC with a supported current desktop distribution. An Apple Silicon Mac, ARM Windows PC, or older distro needs a separate architecture/hardware check. This is an availability and migration assessment, not an installation-tested lockfile.

## How to read the inventory

- **APT/DNF candidate**: a likely distro packaging route; exact package name, enabled repositories and version must be resolved against the selected OS release. This is not a verified command to copy verbatim.
- **Vendor DEB/RPM/APT/DNF**: vendor distribution, often requiring an additional repository. A downloadable DEB/RPM alone does not imply automatic updates.
- **Linux build / upstream**: the software exists on Linux, but may need a tarball, AppImage, language package manager, or compilation. This does not promise a distro package.
- **Native** in the Windows column means a Windows application/tool exists, not that a WinGet manifest was checked.
- **WSL** means running the Linux program inside Windows. It is not a native Windows port and does not grant Linux tools full visibility/control of the Windows host, disks, firewall or hardware.
- **No exact port identified** is a migration gap, not a statement about every unofficial fork or Wine workaround.

Linked entries were checked against current primary documentation. Other entries are a platform baseline and packaging candidates, not individual fresh release/package verification. No runtime, feature-parity or data-migration tests were performed.

## Which Linux distribution fits this list?

For your preference for APT and your mix of commercial desktop software, **Ubuntu LTS is my practical first choice**. It receives explicit vendor instructions more often than Debian; Debian can still work, but an Ubuntu DEB/repository is not automatically supported on Debian. TablePlus and Kiro illustrate the release-specific packaging issue.

**Fedora is also viable**: use DNF for system/developer dependencies, vendor RPM repositories where offered, and Flatpak for ordinary desktop apps. Expect occasional COPR packages, AppImages or upstream installers. `dnf` is the normal dependency-resolving frontend for RPM packages; prefer `dnf install ./app.rpm` over bare `rpm -i`.

Do not use sandboxed GUI packages as a blanket substitute for host-integrated developer tooling, VPN daemons, SSH agents or hardware utilities. For example, 1Password documents integration limitations in sandboxed packages.

Windows retains more commercial desktop apps (Office, Affinity, iMazing, AltServer) and can run the Unix environment in WSL. It still does not replace macOS for Xcode, Apple SDKs, Apple simulators or Apple-specific utilities.

## Important current findings

- 1Password, VS Code, DBeaver, Mullvad, OpenCode Desktop, TablePlus and Zedis provide DEB/RPM routes; see their rows for sources.
- AdGuard and AdGuard VPN have Linux command-line applications, not the same GUI as on Mac/Windows.
- Ghostty runs on Linux: Ubuntu 26.04 has an APT package; older Ubuntu/Debian use a community DEB or other route, and Fedora has a community COPR RPM.
- Current OpenAI documentation offers the desktop app on Linux in preview, with Ubuntu/Debian/Fedora installation guidance. The old Codex app documentation now redirects to ChatGPT desktop documentation. Do not rely on older statements that only the CLI is available on Linux.
- Superset has an experimental Linux AppImage; its current install page says Windows is not yet available.
- TablePro's Linux version is under development and not installable yet. Zedis does provide Linux and Windows releases.
- Cyberduck's Linux product is the `duck` CLI, not the desktop GUI. Parsec's Linux app is a client and cannot host.

## What must change in install.sh

**Do not run this installer unchanged on Linux or Windows.** It is a macOS provisioning script, not merely a portable list of packages.

| Current behavior                                                                   | Linux migration                                                                                                | Windows migration                                                        |
| ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `sw_vers`, macOS minimum version, Time Machine/full-disk-access check              | Detect `/etc/os-release`, CPU architecture and distro release                                                  | Windows version detection in PowerShell; separate WSL detection          |
| `brew bundle`, casks, `mas` and mandatory Infuse install                           | Separate APT/DNF/vendor/Flatpak/upstream lists; remove Mac App Store prerequisite                              | Native app installation plus separate WSL package list                   |
| Finder, Dock, Siri, Spotlight, trackpad, Safari and `defaults`/PlistBuddy settings | Replace with selected GNOME/KDE settings only where useful                                                     | Replace with Windows settings only where useful                          |
| `caffeinate`                                                                       | Desktop power settings or `systemd-inhibit`                                                                    | Windows sleep/power controls                                             |
| `/opt/homebrew`, `/usr/local`, `~/Library`, `/Applications`                        | Use OS-appropriate paths; user tools can live in `~/.local/bin`                                                | Windows paths and environment variables; WSL paths separately            |
| `pinentry-mac` in GPG config                                                       | Installed Linux pinentry path                                                                                  | Gpg4win pinentry or separate WSL agent                                   |
| `xcode-select`, `xcodebuild`, Apple SDK configuration                              | Cannot reproduce Apple build environment; retain access to a Mac                                               | Same limitation                                                          |
| Java link under `/Library/Java/JavaVirtualMachines`                                | Install the required JDK and configure `JAVA_HOME`/alternatives                                                | Install JDK and configure `JAVA_HOME`                                    |
| `launchctl`, macOS application firewall                                            | systemd/OpenSSH plus chosen Linux firewall                                                                     | Windows services, OpenSSH and Windows Firewall                           |
| `pip install` into global Python                                                   | venv/uv/pipx, respecting externally managed distro Python                                                      | Isolated Python environments                                             |
| fish login shell and `/etc/shells`                                                 | Usable Linux concept; resolve fish path                                                                        | Applies inside WSL; no direct PowerShell login-shell equivalent          |
| dotfile symlinks                                                                   | Mostly portable in principle; cloned dotfiles were not audited                                                 | WSL easiest; native Windows configs and symlink permissions differ       |
| `remme` helper                                                                     | Mac-only: PlistBuddy, app bundles and Library paths; replace with package-manager uninstall                    | Replace with Windows uninstall tools                                     |
| `git-show-lfs` helper                                                              | Mostly portable but fix shell assumptions: `/bin/sh` with `$'\n'` and `echo -e` is not portable to Debian dash | Bash/WSL route; it lists Git pack objects, not specifically LFS payloads |
| `mkv2mp4` helper                                                                   | Bash + FFmpeg is portable; actual streams must be compatible with MP4                                          | Bash/WSL or rewrite wrapper for PowerShell + FFmpeg                      |

Two existing behaviors also should not be carried into a new installer: the SSH block uses separate `tee` calls that overwrite `sshd_config`, and answering `Y` to the backup prompt causes existing linked config paths to be deleted without this script making a backup. Those are observed directly in the source, not migration-specific platform limitations.
